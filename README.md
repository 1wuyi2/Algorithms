# 南开大学学院级智能排课系统

这是一个面向南开大学学院老师端的智能排课后端项目。当前重点不是先做完整前端，而是先把排课系统的核心后端能力搭起来：数据建模、冲突检测、冲突图构建、自动排课算法、课表评价、后端 API，以及基础版 AI 辅助排课分析。

项目当前不接入真实教务系统，也暂时不导入真实课程数据。后续等选课手册 PDF、CSV 或 Excel 数据准备好后，再单独做数据导入与清洗模块。

## 当前定位

当前主线：

- 老师端学院自动排课
- 先做课程到时间槽的排课
- 教室分配暂时后置，因为目前还没有教室容量、类型、校区、可用时间等真实数据
- 前端暂时不是重点，当前保留一个老师端静态原型

暂不作为当前主线：

- 学生端个性化推荐
- 真实教务系统对接
- 完整数据库持久化
- 基于外部大模型的 AI 对话功能

## 已完成内容

### 1. 数据模型

代码位置：`src/models/`

已定义核心实体：

- `Course`：课程
- `Teacher`：教师
- `ClassGroup`：班级 / 教学班
- `Room`：教室
- `TimeSlot`：时间槽
- `ScheduleAssignment`：排课结果
- `Campus`：校区，当前包含津南校区和八里台校区
- `RoomType`：教室类型

### 2. 南开规则配置

代码位置：`src/config/`

当前已记录的南开排课规则：

- 周一到周日都可能排课
- 每天 14 节课
- 有晚课
- 排课时间范围为 08:00 到 22:00
- 晚饭时间为 17:40 到 18:30
- 上午前两节课后休息 20 分钟
- 下午前两节课后休息 20 分钟
- 其他课间休息 10 分钟
- 校区包含津南校区和八里台校区

注意：官方每节课的精确起止时间还未录入，后续需要根据南开正式作息表补充。

### 3. 冲突检测

代码位置：`src/constraints/`

当前支持检测：

- 同一教师冲突
- 同一班级冲突
- 固定时间冲突
- 教师不可用时间
- 班级不可用时间
- 教室不可用时间
- 教室容量不足
- 教室类型不匹配
- 校区不匹配

冲突检测结果不仅返回是否冲突，还会返回冲突原因，方便后端调试和后续页面展示。

### 4. 冲突图构建

代码位置：`src/graph/`

已实现课程冲突图：

- 每门课程是一个节点
- 两门课存在冲突时连一条边
- 支持邻接表输出
- 支持查询课程节点度数
- 每条边保留冲突原因

该模块是后续图染色排课算法的基础。

### 5. 排课算法

代码位置：`src/algorithms/`

当前已实现两个基础算法：

- 贪心图染色排课：速度快，用于快速生成初步课表
- 回溯搜索 / 约束满足排课：可作为对比算法，在小规模数据下寻找更完整方案

当前算法主要完成“课程 -> 时间槽”的分配，不做正式教室分配。

### 6. 课表评价

代码位置：`src/evaluation/`

当前可以评价：

- 是否存在未排课程
- 是否有未知课程
- 是否重复给同一课程排课
- 冲突课程是否被排到同一时间槽
- 教室是否不存在
- 同一教室同一时间是否重复占用
- 教室容量是否满足
- 教室类型是否匹配
- 校区是否匹配

输出包括：

- 课表评分
- 是否可行
- 错误列表
- 警告列表

### 7. 后端 API

代码位置：`src/api/`

当前提供基础 HTTP API：

- `GET /health`：健康检查
- `POST /schedule/greedy`：运行贪心图染色排课
- `POST /schedule/backtracking`：运行回溯搜索排课
- `POST /schedule/evaluate`：评价课表质量
- `POST /assistant/analyze`：生成 AI 辅助排课分析和优化建议

当前 API 不依赖 Flask / FastAPI，只使用 Python 标准库，方便在没有额外依赖的环境中运行。

### 8. AI 辅助排课基础版

代码位置：`src/assistant/`

当前实现的是规则化、可解释的 AI 辅助分析模块，不调用外部大模型。

目前能力：

- 统计课程冲突密度
- 找出高冲突课程
- 对比贪心算法和回溯搜索结果
- 根据课表评价结果判断风险等级
- 输出可读的优化建议

后续可以在此基础上接入大模型，把结构化建议改写成更自然的说明。

### 9. 老师端静态原型

代码位置：`web/teacher/`

当前保留一个简单老师端页面原型，包含：

- 基础数据管理
- 自动排课入口
- 课表展示
- 冲突提示

由于现在暂时不继续做前端，该部分只作为后续联调参考。

## 启动后端 API

在项目根目录运行：

```bash
python -m src.api.server
```

默认地址：

```text
http://127.0.0.1:8000
```

健康检查：

```text
GET http://127.0.0.1:8000/health
```

主要内容：

- 增加教师负载分析

- 增加高风险课程解释

### 任务 D：数据导入与清洗

目标：等课程数据准备好后，将南开选课手册 PDF、CSV 或 Excel 转换为系统可用数据。

建议流程：

1. 判断 PDF 类型：可复制文字、表格型 PDF、扫描图片 PDF
2. 抽取课程号、课程名、学分、周学时、教师、开课学院、课程类别、上课对象等字段
3. 转换为 CSV、JSON 或数据库表
4. 做字段校验和人工复核
5. 再导入排课系统

### 任务 E：教室分配

目标：等拿到教室数据后，再实现完整的“课程 -> 时间槽 -> 教室”排课。

需要数据：

- 教室编号
- 教室名称
- 校区
- 教学楼
- 容量
- 教室类型
- 可用时间

### 任务 F：真实南开规则补充

目标：让系统更贴近南开真实排课规则。

待确认信息：

- 每节课官方起止时间
- 上午、下午、晚课精确节次划分
- 是否允许跨校区连续排课
- 实验课、体育课、实践课等特殊课程规则
- 教师偏好时间或学院特殊规则
