# 南开大学学院级智能排课系统

这是一个面向南开大学学院老师端的智能排课后端项目。当前重点不是先做完整前端，而是先把排课系统的核心后端能力搭起来：数据建模、冲突检测、冲突图构建、自动排课算法、课表评价、后端 API，以及基础版 AI 辅助排课分析。

项目当前不接入真实教务系统，也暂时不导入真实课程数据。后续等选课手册 PDF、CSV 或 Excel 数据准备好后，再单独做数据导入与清洗模块。

## 当前定位

本项目最终目标是形成一个较完整的南开大学学院级智能排课系统，功能范围包括：

- 老师端学院自动排课
- 老师端前端管理页面
- 统一登录入口与师生端页面分流
- 学生端个人课表和课程推荐页面
- 后端排课 API
- 数据导入、清洗与数据库持久化
- 学生端个性化推荐
- 真实教务系统对接
- 基于外部大模型的 AI 对话和排课解释

当前实现进度上，已经优先完成后端核心能力，包括数据模型、冲突检测、冲突图、排课算法、课表评价、后端 API、基础版 AI 辅助分析，以及学生端个性化推荐的最小可用版本。由于目前还没有真实课程数据和教室数据，数据导入、数据库持久化、完整教室分配、真实教务系统对接和外部大模型对话会在后续任务中继续推进。

当前正式算法主要完成“课程 -> 时间槽”的分配；“课程 -> 时间槽 -> 教室”的完整排课会在拿到教室数据后继续完善。

## 已完成内容

### 1. 数据模型

代码位置：`src/models/`

已定义核心实体：

- `Course`：课程
- `Teacher`：教师
- `ClassGroup`：班级 / 教学班
- `Room`：教室
- `TimeSlot`：时间槽
- `ScheduleAssignment`：排课结果
- `Campus`：校区，当前包含津南校区和八里台校区
- `RoomType`：教室类型

### 2. 南开规则配置

代码位置：`src/config/`

当前已记录的南开排课规则：

- 周一到周日都可能排课
- 每天 14 节课
- 有晚课
- 排课时间范围为 08:00 到 22:00
- 晚饭时间为 17:40 到 18:30
- 上午前两节课后休息 20 分钟
- 下午前两节课后休息 20 分钟
- 其他课间休息 10 分钟
- 校区包含津南校区和八里台校区

注意：官方每节课的精确起止时间还未录入，后续需要根据南开正式作息表补充。

### 3. 冲突检测

代码位置：`src/constraints/`

当前支持检测：

- 同一教师冲突
- 同一班级冲突
- 固定时间冲突
- 教师不可用时间
- 班级不可用时间
- 教室不可用时间
- 教室容量不足
- 教室类型不匹配
- 校区不匹配

冲突检测结果不仅返回是否冲突，还会返回冲突原因，方便后端调试和后续页面展示。

### 4. 冲突图构建

代码位置：`src/graph/`

已实现课程冲突图：

- 每门课程是一个节点
- 两门课存在冲突时连一条边
- 支持邻接表输出
- 支持查询课程节点度数
- 每条边保留冲突原因

该模块是后续图染色排课算法的基础。

### 5. 排课算法

代码位置：`src/algorithms/`

当前已实现两个基础算法：

- 贪心图染色排课：速度快，用于快速生成初步课表
- 回溯搜索 / 约束满足排课：可作为对比算法，在小规模数据下寻找更完整方案

当前算法主要完成“课程 -> 时间槽”的分配，不做正式教室分配。

### 6. 课表评价

代码位置：`src/evaluation/`

当前可以评价：

- 是否存在未排课程
- 是否有未知课程
- 是否重复给同一课程排课
- 冲突课程是否被排到同一时间槽
- 教室是否不存在
- 同一教室同一时间是否重复占用
- 教室容量是否满足
- 教室类型是否匹配
- 校区是否匹配

输出包括：

- 课表评分
- 是否可行
- 错误列表
- 警告列表

### 7. 后端 API

代码位置：`src/api/`

当前提供基础 HTTP API：

- `GET /health`：健康检查
- `POST /auth/login`：根据学工号和密码完成登录认证，并返回用户身份
- `POST /schedule/greedy`：运行贪心图染色排课
- `POST /schedule/backtracking`：运行回溯搜索排课
- `POST /schedule/compare`：对比贪心图染色和回溯搜索结果
- `POST /schedule/evaluate`：评价课表质量
- `POST /assistant/analyze`：生成 AI 辅助排课分析和优化建议
- `POST /student/recommend`：根据学生画像和当前课表生成个性化课程推荐

当前 API 不依赖 Flask / FastAPI，只使用 Python 标准库，方便在没有额外依赖的环境中运行。

### 8. AI 辅助排课基础版

代码位置：`src/assistant/`

当前实现的是规则化、可解释的 AI 辅助分析模块，不调用外部大模型。

目前能力：

- 统计课程冲突密度
- 找出高冲突课程
- 对比贪心算法和回溯搜索结果
- 根据课表评价结果判断风险等级
- 输出可读的优化建议

后续可以在此基础上接入大模型，把结构化建议改写成更自然的说明。

### 9. 老师端静态原型

代码位置：`web/teacher/`

当前保留一个简单老师端页面原型，包含：

- 基础数据管理
- 自动排课入口
- 课表展示
- 冲突提示

由于现在暂时不继续做前端，该部分只作为后续联调参考。

### 10. 学生端个性化推荐基础版

代码位置：

- 推荐模块：`src/recommendation/`
- API 解析与服务：`src/api/schemas.py`、`src/api/services.py`
- 测试文件：`tests/test_student_recommender.py`、`tests/test_student_api_services.py`

### 主要功能

- 支持学生画像输入，包括学生 ID、专业、年级、已修课程和兴趣方向；
- 支持候选课程信息输入，包括课程 ID、课程名称、课程类型、教师、教室、星期、节次和起止周；
- 支持学生当前课表输入，并根据已有课表判断推荐课程是否存在时间冲突；
- 支持固定必选课程 ID，固定必选课程会参与课表占用和冲突检测；
- 推荐结果中返回课程 ID、课程名称、课程类型、推荐分数、冲突状态和推荐理由；
- 支持通过参数控制是否过滤时间冲突课程；
- 提供相关单元测试，验证推荐排序、冲突检测、固定必选课程和 API 返回结果。
### 11. 数据导入、数据库与持久化

代码位置：`src/database/`、`src/importer/`、`src/persistence/`、`scripts/import_catalog.py`

**状态：已完成**

已完成功能：

- **数据库设计**：基于 SQLAlchemy 定义了 `courses`、`teachers`、`classrooms`、`time_slots`、`schedule_results` 等表，支持多学期数据隔离。
- **选课手册解析**：使用 `pdfplumber` 解析 PDF 表格，固定列顺序提取课程号、课程名、模块、名额、教师、星期、节次、周次、教室等信息。
- **数据清洗**：自动解析星期、节次，推算周学时，识别校区（八里台/津南/泰达）。
- **数据校验**：检查课程号有效性、课程名非空、名额合理性等，并给出警告。
- **导入脚本**：`scripts/import_catalog.py` 支持命令行指定 PDF 路径和学期，自动去重，避免重复导入。
- **API 接口**：`GET /courses?semester=xxx` – 按学期返回课程列表（默认 500 条）。

> **详细使用指南**（环境准备、导入步骤、验证方法、与其他模块集成、常见问题）请参见后文“数据导入模块使用指南”章节。

### 数据导入步骤

1. **准备选课手册 PDF 文件**，将文件放在本地任意目录（例如 `./选课手册/` 或 `~/Documents/`）。

2. **运行导入脚本**，通过 `--file` 参数指定 PDF 文件的路径，通过 `--semester` 参数指定学期（格式如 `2025-2026-1`）：

   ```bash
   # 通用命令格式
   python scripts/import_catalog.py --file "<选课手册文件路径>" --semester "<学期标识>"

   # 示例：导入第一学期（请替换为实际路径）
   python scripts/import_catalog.py --file "./选课手册/2025-2026学年第一学期选课手册.pdf" --semester "2025-2026-1"

   # 示例：导入第二学期
   python scripts/import_catalog.py --file "./选课手册/2025-2026学年第二学期选课手册.pdf" --semester "2025-2026-2"
   ```

   脚本会自动：
   - 跳过前 11 页非课程内容
   - 解析表格并清洗数据
   - 将课程存入 `courses` 表，教师和教室去重存入 `teachers` 和 `classrooms` 表
   - 打印导入汇总信息（课程数、教师数、教室数）

3. **添加新学期数据**：更换 `--file` 和 `--semester` 参数再次运行即可，已存在的教师和教室会被自动跳过，课程通过 `(course_code, semester)` 唯一约束避免重复。

### 验证数据导入是否成功

#### 方法二：通过 API 验证

### 常见问题

- **导入时报唯一约束错误**：说明该学期数据已部分存在，请先运行清理脚本删除该学期课程，再重新导入。
  ```python
  # clean_semester.py
  from src.database.session import init_db, get_session
  from src.database.models import CourseDB
  init_db()
  session = get_session()
  session.query(CourseDB).filter(CourseDB.semester == "2025-2026-2").delete()
  session.commit()
  ```

- **API 返回 404**：确认 `src/api/server.py` 中已添加 `/courses` 路由，并重启服务器。
